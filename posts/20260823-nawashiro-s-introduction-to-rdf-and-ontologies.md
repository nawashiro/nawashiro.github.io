## 「文書のウェブ」と「データのウェブ」の決定的違い `回答済み`

### 問題

HTML のタグ（`<h1>` など）と XML のユーザー定義タグ（`<author>` など）だけでは、なぜセマンティック・ウェブが目指す「コンピュータによる自動的なデータ統合」を実現できないのですか？RDF のデータモデルが XML のツリー構造よりも優れている点に触れて説明してください。

### 回答

XML は文書の構造（syntax）を定義するものです。同じデータ内容でも、タグの順序が異なると異なる文書として扱われてしまいます。

XML はツリー構造です。タグの階層が変わると論理が変わってしまいます（ordered labeled tree）。

このため、2 つのデータを結合することはかなり難しいです。

RDF はグラフ構造を持ち（点と矢印）、グローバルに一意な識別子（URI）を使います。異なる場所にあるデータであっても、データ（点と矢印）を重ね合わせることができます。論理的に正しく、自動的にグラフを結合できます。

サザエとマスオの例を出します。

RDF では個別の事実を記述します。 サザエが結婚している相手はマスオである、と記述します。

XML でもタグでそのような構文を作ることができます。ですが、タグの意味は人間の合意で決まります。計算機は自動的に意味（結婚がどのような性質を持つか）を知ることができません。

RDF ではサザエ・結婚・マスオを URI で記述します。URI はグローバルに一意で、階層構造を持ちます。語彙（名前空間）が異なることがわかります。そのため、食べ物の<ruby>栄螺<rt>さざえ</rt></ruby>や別文化圏の結婚と区別できます。

オントロジーでは、語彙が持つ一般的な性質やルールを記述します。 ここでいう結婚は人間どうしのもので、一方的な関係でなく対称性があることを記述します。

これらによって自動的に明示されていない事実を推論できます。有限時間で計算を終えて正解を出す（決定可能）ことができます。（OWL DL は一階述語論理の決定可能な部分集合である記述論理を基礎としています）

サザエが結婚している相手がマスオならば、マスオは人間で、マスオが結婚している相手はサザエである、という明示されていない知識を導きます。

## URI の役割と「名前」の本質 `回答済み`

### 問題

Linked Data の原則において、なぜ単なる識別子ではなく「HTTP URI」を使用し、それを「デリファレンス（参照）」可能にすることが重要なのですか？もし世界中の開発者が独自の ID 体系（LSID や DOI など）を使い続けた場合、ウェブ全体の相互運用性にどのような影響が出るか考察してください。

### 回答

LSID や DOI は、独自の ID 体系のもと制御下に置こうとします。

HTTP URI（DNS）は既に確立された権限委譲の仕組みで、既存のウェブ・アーキテクチャをそのまま活用できます。

参照可能とは、標準の手段（RDF, SPARQL）で URI を辿れば定義や関連データを取得できることを言います。未知のデータであっても性質や出典を機械的に辿ることができます。

参照可能でなければ、人間の暗黙の合意や知識を使うことになり、計算機はその URI の性質がわからなくなってしまいます。

もし世界中の開発者が独自の ID 体系を使い続けた場合、ウェブ上のデータを結合することが困難になります。ウェブの付加価値は、予期せぬ再利用（unexpected re-use）にあります。相互運用が分裂したり、特定のシステムに閉じ込められた孤島ができたりします。

共通の ID 体系があれば、データを相互に接続する機会が生まれ、誰でも既存の URI に新たな事実を書き足したり（Open World Assumption）、明記されていない事実を推論できるなど、価値が生まれます。

## 開世界仮説 (OWA) の実務的影響 `回答済み`

### 問題

従来のデータベース（閉世界仮説: CWA）では「記述がない＝偽（存在しない）」とみなされますが、セマンティック・ウェブ（開世界仮説: OWA）ではどのように解釈されますか？この違いが、例えば「特定の講義を履修している学生リスト」を検索するシステムの回答にどのような差を生むか具体例を挙げて説明してください。

### 回答

CWA（閉世界仮説）では、収録されていない知識を事実として存在しないと捉えます。つまり、その事実を否定します。

OWA（開世界仮説）では、ウェブの現実を前提にします。ウェブはつねに不完全です。OWA は不完全さを許容します。特定のデータベースに収録された知識を「その分野の全知識」とはみなしません（Incomplete knowledge）。

なぜなら、ある瞬間にあるデータベースを見たところで、その後に新たな知識が追加されるかもしれないし、ほかのデータベースに別の知識が書いてあるかもしれないからです。

以下のいずれかを満たすときだけ、事実を否定します。

1. 明示的な否定の知識を発見する。
2. 推論エンジンがオントロジーに定義された論理制約と照らして矛盾（Inconsistency）を検出する（充足不可能、Unsatisfiable）。

「特定の講義を履修している学生リスト」データベースに、ある人物がこの講義を履修しているか問い合わせる場合を考えます。

CWA システムは知識にない人物を検索したとき、「記述がない=偽」と回答します。

OWA システムでは、まず講義と学生のクラスを考えます。

講義クラスに学生プロパティが定義されている場合、たとえその学生が収録されていなくても、ほかのデータベースに知識がある可能性があります。この場合、「記述がない=不明」と回答します。

以下をすべて満たすときを考えます。

1. 知識では、その人物が学生クラスではなく講師クラスと記述されている。
2. オントロジーの論理制約では、学生クラスと講師クラスは排他（`owl:disjointWith`）と記述されている（講師と学生は掛け持ちできない、という前提）。

推論エンジンは、その人物が講師であり、かつ学生でもある状態が、排他制約に反することを検出します。このように、論理的な不整合があるとき「充足不可能=偽」と回答します。

## プロパティの制約と推論の仕組み

### 問題

オントロジーで `rdfs:domain` や `rdfs:range` を定義することは、単なるデータのバリデーション（入力チェック）以上の意味を持ちます。あるリソースの型が明示されていなくても、プロパティの定義からその型が自動的に「推論」されるプロセスを、具体的なトリプルの例を用いて説明してください。
