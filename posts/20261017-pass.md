## TOC

## モチベーション

鍵が無限に増えていく。パスワードがパスワードを保護し、アカウントが互いを承認していく。非常によろしくない。

私はせっかく GPG スマートカード [^1] を使っているので、鍵管理を GPG に一本化したいと思った。

[^1]: スマートカード: 署名や復号を行う物理デバイス。有名どころでは [Yubikey](https://www.yubico.com/) がある。

今回は GPG が導入済みの前提だ。『なわしろの WWW 入門』シリーズは **なわしろがいろいろなものに入門した記録**であって、万人に向けた入門記事ではないから、今回は GPG の使い方まで書かない。いつか書きたいところだ。

## pass って何？

標準的な Unix のパスワードマネージャーだ。

全てはプレーンテキストだ。ウェブサイトなどの名前でテキストファイルを作成し、GPG で暗号化する。

## 環境

- Fedora 44
- git 2.56.0
- GnuPG 2.4.9
- pass 1.7.4

## インストール

```bash
sudo dnf install pass
```

## pass のセットアップ

使う GPG 鍵のフィンガープリントを確認してくれ。

```bash
gpg --list-secret-keys --keyid-format long --with-subkey-fingerprint
```

これでパスワードストアを作成できる。`$FingerPrint` を書き換えてくれ。

```bash
pass init '$FingerPrint'
```

`~/.password-store` ディレクトリが作成されているはずだ。セットアップは完了だ。

GUI があった方が管理が楽だと思う。[QtPass](https://qtpass.org/) を導入してくれ。

```bash
sudo dnf install qtpass
```

他にやりたいことがなければ、ここで終わって構わない。私は色々やりたいことがあった。

## 既存のパスワードマネージャからインポートする

私は Bitwarden ユーザーなので、まず平文の JSON をエクスポートしてきた。`設定 → 保管庫オプション → エクスポート` を選ぶとダウンロードできる。

これをインポートする。UV が使えれば話が早い。`pass-import` を使う。

> [!CAUTION]
> エクスポートした JSON ファイルは **絶対に外部に送信しないでくれ。** クラウドストレージなども外部のうちだ。
> 
> 終わったらすぐに処分してくれ。これは無防備な機密の塊だ。ゴミ箱とかにうっかり残っているとまずい。

私はパスワードマネージャーに API トークンとかも入れていた。API トークンはすごく長い。

ところが、`pass-import`の強度チェックに使われている `zxcvbn` の最新版は、パスワードを 72 文字に制限している。だからエラーが発生する。なので、今回は古いバージョンを使った。そういう事情がなければ`--with 'zxcvbn==4.4.28'` はいらないかも。

これは検証用のコマンドだ。実行してみて、取り込み予定の件数とか、保存先とかを見よう。問題なさそうかしら。なら `--dry-run` を消して、本番を実行してくれ。

```bash
uv tool run --from pass-import --with 'zxcvbn==4.4.28' pimport \
  pass BitwardenJSON \
  'bitwarden.json' \
  --out "$HOME/.password-store" \
  --path Bitwarden --all --dry-run
```

## git を導入する

パスワードストアで git を始める。GitHub とかでプライベートリポジトリを作ってくれ。

> [!CAUTION]
> **プライベートリポジトリに上げてくれ。** パブリックリポジトリには上げない方がいい。
> 
> パスワードそのものは暗号化されているけれども、サービスの名前は暗号化されていない。

`$Remote` を書き換えてくれ。

```bash
pass git init
pass git remote add origin '$Remote'
pass git push -u origin HEAD
```

以降は pass による変更があれば、自動でコミットされる。QtPass からワンクリックで Pull や Push ができる。

## ブラウザ拡張機能を導入する

[browserpass](https://github.com/browserpass/browserpass-extension) 拡張機能と [browserpass-native](https://github.com/browserpass/browserpass-native) ソフトを使う。native のほうはローカルの pass とブラウザの通信をしてくれる。

> [!NOTE]
> 私は [Zen](https://zen-browser.app/) を使っている。[Firefox](https://www.firefox.com) のディストリビュージョンだ。
> 
> AppImage 版を使った。確認できた範囲では、Flatpak 版は native との連携に問題がありそうだった。

### browserpass-native

私の環境のパッケージマネージャー向けの案内はなかったので、[マニュアルでインストールした](https://github.com/browserpass/browserpass-native#install-manually)。

> [!TIP]
> 後になって AI に調べてもらったら、Fedora 44 公式パッケージにちゃんと入ってるっぽい。
> 
> 本体: [browserpass - Fedora Packages](https://packages.fedoraproject.org/pkgs/browserpass/browserpass/fedora-44.html)
>  
>  Firefox 版 (本体も一緒に入る): [browserpass-firefox - Fedora Packages](https://packages.fedoraproject.org/pkgs/browserpass/browserpass-firefox/fedora-44.html)
>  
>  私はまだ検証していない。いつかどうにかしたい。

[リリース 3.1.2](https://github.com/browserpass/browserpass-native/releases/tag/v3.1.2) の `browserpass-linux64-3.1.2.tar.gz` を使った。ダウンロードしたものが心配なら署名検証してくれ。パスワードへアクセスする実行ファイルだから、気にする人は気にすると思う。私は面倒なのでしなかった。たぶんした方がいい。

解凍して Make していく。

```bash
make BIN=browserpass-linux64 configure      # ホストJSONファイルを作成
sudo make BIN=browserpass-linux64 install   # アプリをインストール
```

[ブラウザの設定をする。](https://github.com/browserpass/browserpass-native#configure-browsers) 使っているブラウザ向けにシンボリックリンクを作るかんじだ。私は Firefox 引数を使った。

```bash
make -f /usr/lib/browserpass/Makefile hosts-firefox-user
```

## パスキーを導入する

[passless](https://github.com/pando85/passless) を使う。pass を保存先に使うソフトウェア FIDO2 認証器だ。

> [!NOTE]
> データは GPG で暗号化して保存するわけなので、ハードウェア認証器みたいな隔離が得られるわけではないよ。盗まれる経路はそれなりにあるんだよね。

### インストールする

[インストールする。](https://github.com/pando85/passless#installation-1)

```bash
# リポジトリをクローンする
git clone https://github.com/pando85/passless.git
cd passless

# インストールする
make install
```

インストールした後、色々やることがある。この辺はうろ覚えなので、[公式の案内](https://github.com/pando85/passless/blob/master/docs/PERMISSIONS.md) をよく読んでほしい。

### トラブルシュート: サービスが実行ファイルを見つけられない

```bash
systemctl --user status passless.service --no-pager -l
```

```bash:出力
passless.service: Unable to locate executable 'passless': No such file or directory
```

実行ファイルを見つけられないようだ。

サービスの設定をする。このコマンドを打つと編集できる。

> [!NOTE]
> 気をつけてほしい。書き込んで反映される行と、反映されない行がある。

```bash
systemctl --user edit passless.service
```

サービスの起動先を明示する。元の指定を消してパスを入れている。

```ini:passless.service
[Service]
ExecStart=
ExecStart=%h/.cargo/bin/passless
```

再始動する。

```bash
systemctl --user daemon-reload
systemctl --user restart passless.service
```

### トラブルシュート: パスが通っていない

パスが通っていなかったので入れておく。

```bash
export PATH="$HOME/.cargo/bin:$PATH"
```

## 認証を試してみる

[WebAuthn.io](https://webauthn.io/) で、パスキーを試してみる。

ちゃんと通知が来たけど、知らないドメインからも認証の要求が来ている。これはなんだろう。

![make.me.blinkからも要求が来ている](Screenshot%20From%202026-10-15%2016-52-11.webp)

これは認証先の ID としてドメイン名を使っているらしい。実際に通信しているわけではないっぽい。

なんと、Firefox が認証器を選ぶために送るダミーの要求だそうだ。

[mozilla/authenticator-rs](https://github.com/mozilla/authenticator-rs/blob/598ce022c98dd1378fac25e9b2ac112ec4ade3ba/src/ctap2/commands/make_credentials.rs#L677-L682)

```rust:src/ctap2/commands/make_credentials.rs
RelyingParty::from("make.me.blink"),
Some(PublicKeyCredentialUserEntity {
	id: vec![0],
	name: Some(String::from("make.me.blink")),
	..Default::default()
}),
```

passless のパスキー実装だが、もちろん完全というわけではない。サービスによって使えたり使えなかったりする。

パスキーを使うときに、たまにプライバシー情報へのアクセスの確認が出る。承諾したら認証を断られて、拒否したら使えたりした。

## Android でも使う

pass の Android 実装には [Password Store (Passkey Edition)](https://f-droid.org/packages/app.passwordstore.pando85/) がある。

> [!NOTE]
> 本家の Password Store は、今では開発が停止している。有志のフォークがいろいろあって、Passkey Edition はそのひとつだ。

[OpenKeychain](https://www.openkeychain.org/) をインストールするとスマホでも GPG が使える。

Password Store 側の `Settings → PGP Settings → OpenPGP backend → OpenKeychain` から連携を設定できる。

あとは git が使えれば野生の勘でどうにかなるだろう。

git リポジトリに OpenKeychain 経由で認証する方法はなさそうだった。SSH 鍵を生成する機能があったので、こいつで普通に認証した。
