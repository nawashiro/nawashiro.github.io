## Context

現行の `pages/_document.tsx` は `caramellatte` を選択し、`styles/global.css` も同テーマを有効化しています。一方、`e2e/theme.spec.ts` だけが過去の `nawashiro` 固定値を検証しています。テーマ名はデプロイ時に切り替え得るため、E2Eテストは特定名に依存しない必要があります。

## Goals / Non-Goals

**Goals:**

- HTMLがテーマ属性を宣言していることをE2Eで検証する。
- テーマ名の手動切替でテストコードを変更しなくて済むようにする。
- 現行のテーマ設定と既存のサイト表示を変更しない。

**Non-Goals:**

- ブラウザ上のテーマ切替UIの追加。
- DaisyUIテーマの追加・削除・再定義。
- テーマ名のallowlistやCSS適用結果の検証。

## Decisions

### 1. テストは `data-theme` の非空値だけを検証する

`toHaveAttribute("data-theme", /.+/)` を使い、属性が存在して空でないことを確認します。`nawashiro` や `caramellatte` のような具体的な値はテストに埋め込みません。

**理由:** テーマの選択は意図的に変更可能な運用であり、特定名を期待すると設定変更を誤って回帰として扱うためです。テーマの妥当性や配色そのものは、この小さなE2Eテストの責務に含めません。

**検討した代替案:**

- テーマ名のallowlistをテストに持つ案は、設定とテストの二重管理になるため採用しません。
- テストを削除する案は、`data-theme` 属性の存在確認という有用な最低限の契約まで失うため採用しません。

## Risks / Trade-offs

- [設定ミスで未知のテーマ名を指定しても検出できない] → DaisyUIのテーマ設定確認はビルド・目視確認または別の表示回帰テストの責務とし、この変更では扱わない。
- [テーマ属性が空でも検証を通る可能性] → 正規表現で1文字以上を要求する。

## Migration Plan

1. `e2e/theme.spec.ts` の固定値を非空属性検証へ変更する。
2. 対象E2E、ユニットテスト、OpenSpec検証を実行する。
3. 問題があればテスト変更だけを戻せば、現在のテーマ設定には影響しない。
