# GitHub Markdown Alerts Specification

## Purpose

記事原稿で使うGitHub Alerts記法をサイト内でも意味のある通知として表示し、GitHubから移したMarkdownの可読性と情報の重要度を保つ。

## ADDED Requirements

### Requirement: 標準アラート記法を表示する

記事のMarkdownに、単独の先頭行として`[!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]`、または`[!CAUTION]`を持つ引用がある場合、サイトはマーカー文字列を本文へ表示せず、対応するアラートのタイトルと本文を表示しなければならない（SHALL）。

#### Scenario: NOTEをタイトルと本文で表示する

- **WHEN** 記事に`> [!NOTE]`と、その後の引用本文がある
- **THEN** サイトは`Note`のタイトルと引用本文を表示する
- **THEN** `[!NOTE]`というマーカー自体は表示しない

#### Scenario: 5種類のアラートを区別する

- **WHEN** 記事に5種類の標準マーカーをそれぞれ含む引用がある
- **THEN** サイトは各マーカーに対応する`Note`、`Tip`、`Important`、`Warning`、`Caution`のタイトルを表示する
- **THEN** 各アラートの種類を通常の引用と区別できる表示にする

#### Scenario: 本文が空のアラートを表示する

- **WHEN** 記事にマーカー行と空の引用行だけを持つアラートがある
- **THEN** サイトは対応するタイトルを表示する
- **THEN** `[!TYPE]`というマーカーを表示しない

### Requirement: アラート本文のMarkdownを保持する

アラートの本文は、記事で利用できる通常のMarkdownとGFMの表示結果を保持しなければならない（SHALL）。

#### Scenario: 本文の書式を保持する

- **WHEN** アラート本文にリンク、強調、リスト、コード、または複数の段落がある
- **THEN** サイトは各要素を通常の記事本文と同じ意味で表示する
- **THEN** 本文の順序と内容を変更しない

#### Scenario: 静的出力とフィードで本文を保持する

- **WHEN** 記事を静的生成し、同じ記事をRSS、Atom、またはJSON Feedへ出力する
- **THEN** 各出力はアラートのタイトルと本文を含むHTMLを使用する
- **THEN** ブラウザ側の追加処理がなくても本文を読める

### Requirement: 非アラートの引用を保持する

標準アラートとして認識できない引用は、既存の通常引用として表示しなければならない（SHALL）。

#### Scenario: 通常の引用を変更しない

- **WHEN** 引用の先頭行が標準アラートマーカーではない
- **THEN** サイトは引用の本文と既存の引用表示を保持する

#### Scenario: 未知のマーカーを変更しない

- **WHEN** 引用の先頭行が`[!DANGER]`などの未対応マーカーである
- **THEN** サイトはそれをアラートへ変換せず、通常の引用としてマーカーを表示する

#### Scenario: コードフェンス内の文字列を変更しない

- **WHEN** コードフェンスの本文に`[!NOTE]`などの文字列がある
- **THEN** サイトはその文字列をコードとして表示する
- **THEN** コードフェンスをアラートへ変換しない

### Requirement: 静的記事に適したタイトルを提示する

サイトはアラートの種類をタイトル文字列で提示し、静的な記事を読み込んだだけでライブ通知を発生させてはならない（SHALL）。

#### Scenario: 支援技術へタイトルを提示する

- **WHEN** 支援技術がアラートのHTMLを読む
- **THEN** アラートのタイトルと本文をDOMのテキストとして取得できる
- **THEN** 種類をCSSの色や疑似要素だけに依存せず判別できる

#### Scenario: ページ読み込み時に通知を発生させない

- **WHEN** 静的な記事ページを読み込む
- **THEN** アラートは記事本文の一部として表示する
- **THEN** 動的なライブ通知として自動読み上げしない
