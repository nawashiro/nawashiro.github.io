# Spec Delta

## ADDED Requirements

### Requirement: Feedの記事概要へp-summaryを反映する

システムは、決定した空でない`p-summary`をRSSの記事`description`、Atomの記事`summary`、JSON Feedの記事`summary`へ同じ値で出力する（MUST）。システムは、明示した概要を本文抜粋の文字数制限で切り詰めない（MUST）。システムは、概要の選択によって各Feedの記事本文を変更しない（MUST）。

#### Scenario: 装飾と空白を含む概要を3形式へ反映する

- **WHEN** 記事本文がインライン装飾と連続する空白を含む空でない`p-summary`を持つ
- **THEN** システムは子孫テキストを空白正規化した概要を3形式の記事概要へ同じ値で出力する
- **AND** システムは各形式の記事本文を維持する

#### Scenario: 複数の概要から最初の空でない値を使う

- **WHEN** 記事本文が空白だけの`p-summary`と、その後に複数の空でない`p-summary`を持つ
- **THEN** システムは文書順で最初の空でない概要を3形式の記事概要へ出力する

#### Scenario: 長い明示概要を維持する

- **WHEN** 決定した`p-summary`が200文字を超える
- **THEN** システムは明示概要を切り詰めずに3形式の記事概要へ出力する

### Requirement: Feedの既存本文抜粋フォールバックを維持する

システムは、空でない`p-summary`がない記事で既存のFeed用本文抜粋を使用する（MUST）。システムは、本文HTMLのタグを除去し、改行を空白に置換し、前後の空白を除去する（MUST）。システムは、この文字列が200文字を超える場合、先頭200文字に`...`を付ける（MUST）。システムは、200文字以下の場合、この文字列を切り詰めない（MUST）。文字数は既存実装と同じJavaScript文字列のUTF-16コード単位で数える。

#### Scenario: p-summaryがない記事の抜粋を維持する

- **WHEN** 記事本文が`p-summary`を持たない
- **THEN** システムは既存の本文抜粋を3形式の記事概要へ出力する

#### Scenario: 空白だけのp-summaryを持つ記事の抜粋を維持する

- **WHEN** 記事本文のすべての`p-summary`が空または空白だけである
- **THEN** システムは既存の本文抜粋を3形式の記事概要へ出力する

#### Scenario: 短い本文を切り詰めない

- **WHEN** 本文から生成した抜粋が200文字以下である
- **THEN** システムは抜粋へ省略記号を追加しない

#### Scenario: 長い本文を既存の長さで切り詰める

- **WHEN** 本文から生成した抜粋が200文字を超える
- **THEN** システムは先頭200文字と`...`を3形式の記事概要へ出力する
